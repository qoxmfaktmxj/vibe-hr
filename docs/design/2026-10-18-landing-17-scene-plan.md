# 내부 화면 정리 후 랜딩 17장면 설계

날짜: 2026-10-18
상태: 사용자의 후속 구현 승인에 따라17장면 랜딩과 제품별 웹 시연 모션을 적용했다. 구조와 화면은 `2026-10-18-landing-implementation.md`, 모션 흐름과 검증은 `2026-10-18-product-scene-motion.md`에 기록한다. 읽기 시간을 확보하기 위해 실제 루프는7.2~9초로 구성했다.

## 유지하는 결정

- 첫 진입은 제품 소개가 중심이며 로그인 진입점을 명확하게 둔다.
- 실제 제품 UI를 소개한다. 배경 장식만으로 제품을 설명하지 않는다.
- 기존 물결 배경을 그대로 보존하고 갤러리의 한 장면으로 포함한다.
- 제품 화면 16장면과 기존 배경 1장면으로 총 17장면이다.
- 먼저 구도와 설계를 완성한 뒤 사용자의 구현 승인을 받았다. 아래 루프 동작은 제작 사양이며 영상 생성 완료를 뜻하지 않는다.
- 참고한 [Alim Designer](https://alimdesigner.com/)의 공간 탐색 원리를 VIBE-HR의 제품 소개에 맞춘다. 사이트 자산과 작품을 가져오지 않는다.

## 공간 구성

왼쪽 벽에 8장면, 오른쪽 벽에 8장면, 끝 정면에 기존 배경 1장면을 둔다. 중앙 통로에서 화면을 훑고 선택한 화면에 접근한다. 직원 관리에서 조직/근태로 이동한 뒤 중앙 배경을 지나 급여와 운영 화면으로 이어진다.

왼쪽 01~08 → 정면 09 기존 배경 → 오른쪽 10~17

화면을 단순히 같은 크기로 반복하지 않는다. 목록은 가로형 전체 구도, 문서와 프로필은 내용 중심 구도, 조직도는 넓은 구조 구도로 구분한다. 프레임 가장자리와 캡션 규격은 통일한다. 제품 내부의 공통 글자, 아이콘, 모서리와 저장 표시를 그대로 사용한다.

테마는 현재 제품에 있는 팔레트를 사용한다. 각 장면의 테마를 다르게 해도 프레임과 캡션, 랜딩의 기본 브랜드색은 통일한다. 위 경로와 구도는 제품 소스 기준이며 랜딩용 이미지가 모두 준비되었다는 의미는 아니다.

## 입력과 포커스

- 휠/트랙패드: 장면 사이를 이동한다. 이동 중에도 현재 장면 번호와 제목을 표시한다.
- 왼쪽 버튼 드래그: 카메라 시점을 제한된 범위에서 움직인다. 드래그 후 클릭이 잘못 실행되지 않도록 이동 거리를 구분한다.
- 클릭: 선택한 화면을 크게 본다. 제품 화면 속 버튼은 시연 자료이며 실제 업무 쓰기를 실행하지 않는다.
- 키보드: 이전/다음과 Enter로 상세 보기, Escape로 돌아가기를 제공한다. 포커스는 선택한 장면으로 복귀한다.
- 화면 상단: 제품명과 로그인 버튼을 유지한다. 제품 설명은 캔버스 밖 HTML로 제공한다.
- 모바일: 같은 17장면을 읽기 쉬운 세로 목록으로 제공한다. 손가락 드래그와 페이지 스크롤이 충돌하지 않게 한다.
- 모션 감소 또는 WebGL 사용 불가: 정적 목록과 명시적 이전/다음 이동으로 모든 제품 내용을 볼 수 있게 한다.

## 프레임과 모션 제작 기준

제품 화면은 1440px 데스크톱 구도를 기본으로 하고, 화면 안의 민감 정보는 합성 데이터로 구성한다. 실제 고객/직원 정보와 세션 정보, 내부 주소는 공개 자산에 포함하지 않는다. 예시 금액과 인원은 시연 데이터로 표시한다.

한 장면은 정적인 시작, 한 가지 업무 동작, 결과 확인으로 구성한다. 여러 기능을 한 루프에 넣지 않는다. 목표 길이는 약 5~7초이며 실행되는 쓰기 API 없이 재현한다. 마감과 승인, 급여 확정은 확인 단계와 결과 표현을 시연할 뿐 운영 데이터를 변경하지 않는다.

초기에는 포스터를 먼저 표시한다. 현재 보이는 장면 위주로만 움직이며 17개 영상을 동시에 재생하지 않는다. 숨겨진 장면과 비활성 탭은 정지한다. 기존 배경은 갤러리에서 선택되었을 때 기존 장면을 재사용하는 구도를 우선하고 로그인 배경 파일은 수정하지 않는다.

## 다음 구현 순서

1. 이 17장면의 구도와 탐색 순서를 정적 갤러리로 확인한다.
2. 로그인 진입점을 유지하며 공개 제품 소개 경로를 구성한다.
3. 스크롤 이동, 드래그 시점 조절, 선택 확대와 포커스 복귀를 구현한다.
4. 모바일과 모션 감소 대체 화면을 먼저 검증한다.
5. 승인된 구도의 합성 UI 자료를 연결하고, 필요한 장면만 모션 루프로 확장한다.
6. 실제 장치의 초기 로딩, 메모리, 프레임 유지와 한국어 가독성을 측정한 뒤 공개 여부를 검토한다.
