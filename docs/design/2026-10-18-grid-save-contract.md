# HTML 표 전환과 공통 저장 설계

작성: 2026-10-18
결정: 사용자가 관리 목록의 그리드 중심 UX와 명시적 일괄 저장을 승인했다.
현재 범위: 사용자가 승인한 11개 전환 대상의 구현을 적용했다. G05/G06에 이어 나머지 9개를 같은 공통 그리드로 전환했다. 예외 7개와 미연결 1개는 유지하며 최종 검증 결과는 별도 적용 보고서에 기록한다.

## 1. 확정한 저장 원칙

**셀 수정 → 변경 표시 → 저장 버튼 → 변경 건 일괄 반영**을 편집형 관리 목록의 기본으로 한다.

- 행 추가, 셀 수정, 삭제 선택은 화면의 임시 상태만 바꾼다. 저장 전에는 서버에 해당 변경을 반영하지 않는다.
- 저장은 현재 활성 편집 영역의 추가/수정/삭제 예정 행을 모두 처리한다. 변경 없는 전체 데이터를 다시 저장하지 않는다.
- 한 저장 단위는 한 업무 목록 또는 한 직원의 한 이력 탭이다. 서로 다른 메뉴의 변경을 전역 저장 버튼에 섞지 않는다.
- 결재선처럼 부모와 하위 단계가 함께 유효해야 하는 데이터는 하나의 저장 단위로 처리한다.
- 추가/수정/삭제 예정 건수를 표시하고, 원래 값으로 되돌리면 변경 표시를 해제한다. 삭제 예정 행은 저장 전 복구할 수 있다.
- 셀 편집을 종료하고 클라이언트 검증을 수행한 뒤 저장한다. 오류는 해당 행/셀과 연결하고 입력한 내용은 보존한다.
- 서버의 저장 단위는 하나의 트랜잭션을 기본으로 한다. 일부만 반영된 상태를 전체 성공으로 표시하지 않는다. 현재의 개별 POST/PUT/DELETE API는 필요한 batch 계약을 별도로 설계한다.
- 저장 중 중복 요청과 데이터 교체를 막는다. 성공 응답 이후에만 변경 상태를 정리하고, 실패하면 편집 내용을 유지한다.
- 조회, 페이지 이동, 직원 변경, 이력 탭 변경, 메뉴 이동처럼 편집 대상이 바뀌는 동작은 미저장 확인을 거친다. 현재 표준의 `무시하고 이동`과 `취소`를 유지하며 저장은 명시적 저장 버튼에서 수행한다.
- 현재 목록의 정렬이나 열 크기 변경은 편집값을 보존한다. 서버 재조회가 필요한 필터는 미저장 확인 대상이다.
- 읽기 전용 그리드에는 저장 버튼을 만들지 않는다. 실제로 허용된 조회, 다운로드, 상세 보기만 제공한다.

신청 제출, 신청 회수/취소, 승인/반려, 월마감/재오픈, 급여 확정과 같은 업무 상태 전환은 해당 이름의 버튼과 확인 절차를 유지한다. 이 동작들을 편집형 그리드의 저장에 섞지 않는다.

## 2. 전수 확인 범위와 수량

`frontend/src`의 TSX/JSX를 AST로 조사한 결과, **14개 파일에 19개의 네이티브 table 선언**이 있다. 실제 화면에 반복되는 탭과 행을 각각 더한 숫자가 아니라 소스의 표 선언 수다.

| 분류 | 표 선언 수 | 처리 |
| --- | ---: | --- |
| 편집형 그리드 전환 | 6 | 공통 변경 상태와 저장 버튼 적용 |
| 읽기 전용/업무 동작형 그리드 전환 | 5 | 조회 경험 통일, 일반 저장 버튼 없음 |
| 전용 표현 유지 예외 | 7 | 문서, 매트릭스, 단일 대상 상세 |
| 현재 미연결 코드 | 1 | 전환 작업에서 제외하고 그대로 보존 |
| 합계 | 19 | 모든 선언의 판단 기록 |

아래 줄 번호는 조사 시점의 표 시작 위치다. 재사용되는 인사 이력 템플릿은 여러 탭에 적용된다.

## 6. 공통 그리드 디자인과 계약

- 기존 `ManagerPageShell`, `ManagerSearchSection`, `ManagerGridSection`, 공통 검색/도구/페이지 이동 모듈을 사용한다.
- 편집형은 `_status`, `_original`, `_prevStatus`와 공통 변경/삭제 복원 로직을 사용한다.
- 도구 순서는 `query → create → copy → template → upload → save → download`를 유지한다. 화면에 없는 기능을 영구 비활성 버튼으로 채우지 않는다.
- 왼쪽 정보는 페이지 이동 → 전체 건수 → 변경 건수 순서다. 읽기 전용 상세와 고정 12개월 표의 페이지 이동 예외는 등록부와 표준에 함께 명시해야 한다.
- 저장 전 오류와 서버 오류를 구분하고, 저장 실패 시 모든 초안을 유지한다.
- 원본의 동시 변경을 감지하는 방식과 서버 오류를 행/셀로 연결하는 방식은 API별로 확인한다. 현재 없는 버전 필드나 batch 동작을 이미 지원한다고 가정하지 않는다.
- 모바일에서는 컬럼을 억지로 줄바꿈하지 않고, 주요 열 고정과 그리드 내부 가로 스크롤을 검토한다. 화면별 상세 전환도 허용한다.

## 7. 적용 순서와 완료 기준

1. G01 신청서 코드: 기존 batch 경로를 검토하고 한 화면으로 변경 상태, 삭제 복원, 검증, 저장 실패, 미저장 이동을 확정한다.
2. G05/G06 인사 이력: 재사용 템플릿과 탭 단위 저장 계약을 설계한다.
3. G02/G03/G04: 부모/하위 단계와 근무 기간 제약이 있는 관리 목록을 전환한다.
4. G07~G11: 읽기 전용 목록과 업무 버튼을 공통 그리드 구도로 정리한다.
5. E01~E07: 디자인 토큰과 버튼 위치를 맞추고 예외 이유를 등록한다.

완료 기준은 표의 모양뿐 아니라 저장 전 서버 쓰기 0건, 저장 요청 중복 방지, 저장 단위의 원자성, 실패 후 초안 보존, 원래 값 복구, 미저장 조회/탭/직원 이동 보호다. 읽기 전용 영역에는 편집 가능한 셀이나 의미 없는 저장 버튼이 없어야 한다.

그리드 공통 규칙/API 계약 변경은 R2, 권한/급여/일정의 민감한 의미 변경은 R3 경계를 따른다. 전체 전환과 배포가 완료된 것은 아니다.

## 8. G05/G06 적용 기록

발령과 나머지 7개 이력 탭을 `hr-basic-tabs.tsx`의 공통 그리드로 전환했다. 기준 목록의 HTML 표 선언 2개를 제거했다. 원래 11개 전환 대상 중 2개 템플릿을 적용했고 나머지 9개는 후속 범위다. 이력은 기존 직원 상세 응답에서 분류별로 읽으며 로컬50행 페이지 이동을 사용한다. 한 직원의 한 분류 전체 변경 건이 저장 단위다.

- 브라우저: `POST /api/hr/basic/{employeeId}/records/batch`
- Spring: `POST /api/v1/hr/basic/{employee_id}/records/batch`
- 요청: `category`, `items`(신규 id=null, 기존 id와 편집 필드), `delete_ids`
- 응답: 저장된 분류의 `items`, `inserted_count`, `updated_count`, `deleted_count`
- 기존 HR 역할 확인을 유지한다. 직원 쓰기 잠금, 직원/분류 소유권, ID 중복 검증 후 단일 트랜잭션으로 반영한다. 일부 행이 실패하면 모두 되돌린다.
- 기존 테이블을 사용하며 스키마 변경은 없다. 프론트와 Spring을 함께 배포해야 한다.
- 선택 삭제는 표시만 변경하고 저장 전 복원할 수 있다. 신규 행 삭제는 로컬에서 제거한다. 실패하면 초안을 보존하고 미저장 이동을 확인한다.
- 기본 정보도 명시적인 폼 저장을 사용하며, 보낸 선택 필드의 null은 값을 지운다는 의미로 처리한다. 보내지 않은 필드는 유지한다.
- 버전 토큰을 비교하는 낙관적 동시 편집 충돌 검사는 이번에 추가하지 않았다. 기존 서버의 직원 잠금 기준을 따른다.

## 9. 남은 9개 적용 기록

- G01/G02: 신청서 코드와 결재선 템플릿 목록을 `BatchGridManager`로 전환했다. 여러 행과 하위 단계의 변경을 초안으로 유지하고 기존 batch API에 한 번만 보낸다. 삭제 표시 복원, 원래 값 복귀, 실패 후 초안 유지와 조회/이동 보호를 공통 적용했다.
- G03/G04: 조직 근무 배정과 개인 예외 근무조의 즉시 추가/삭제를 제거했다. 조직/사원 선택 후 로컬 행을 만들고 기간, 패턴, 우선순위 등을 편집하여 저장한다. 개인 사원 검색은 이름/사번으로 실제 후보를 선택하고 ID를 보관한다. 기존 일정 생성 버튼과 생성 규칙은 유지한다.
- 근무코드 화면은 좁은 3열 배치에서 각 영역이 충분한 너비를 갖는 구성으로 변경했다. 여러 편집 영역의 미저장 상태를 함께 확인하므로 깨끗한 영역이 다른 영역의 이동 보호를 우회하지 않는다.
- G07/G08/G09: 월별 급여 목록과 퇴직금 임금 산입 근거, 전표 라인을 공통 읽기 전용 그리드로 바꿨다. 명세서와 세금 산출 요약은 기존 문서 표현을 유지한다.
- G10/G11: 휴가 목록은 서버 50행 페이지 이동, 월마감은 12개월 읽기 전용 그리드를 사용한다. 신청/취소/마감/재오픈은 기존 이름과 확인 절차를 유지한다.
- 조회형 공통 도구에서 사용할 수 없는 입력/복사/업로드/저장 버튼을 제거했다. 실제 제공하는 조회와 다운로드만 표시한다.
- 남은 네이티브 표는 예외 7개와 미연결 1개로 총 8개다. 표 전환 대상은 더 이상 네이티브 table을 사용하지 않는다. 예외의 표 마크업과 미변경 파일 해시를 별도로 확인한다.

화면과 검증 자료는 `frontend/output/grid-rollout-20261018/`와 `output/grid-rollout-20261018/`에 기록한다. 편집형 4개의 기존 서버 다건 저장은 실제 PostgreSQL로 중간 실패 전체 롤백과 결재선 부모/단계 원자성을 검증한다. 근무 배정 저장이 일정 자동 생성으로 이어지지 않는 기존 의미도 확인한다.
