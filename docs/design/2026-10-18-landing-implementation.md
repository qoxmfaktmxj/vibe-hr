# 17장면 제품 소개 랜딩 구현

날짜: 2026-10-18
상태: 구현과 로컬 검증 완료. 커밋, 푸시, 운영 배포는 수행하지 않았다.

## 적용 범위

사용자가 승인한 17장면 설계를 공개 첫 화면 `/`에 구현했다. 로그인 여부와 관계없이 제품 소개를 표시하며 상단 로그인과 하단 업무 시작하기가 `/login`으로 이동한다. 업무 경로와 API의 인증 및 권한 규칙은 유지한다.

변경 위험은 공개 UI와 진입 경로에 한정된다. 사용자의 명시적 구현 요청이 `/` 공개 전환을 승인한다. 백엔드 인증, 업무 계산, 데이터베이스, 배포 설정은 변경하지 않았다.

## 구성과 상호작용

- 왼쪽 01~08, 정면 09 물결, 오른쪽 10~17로 구성했다. 오른쪽은 안쪽에서 입구 쪽으로 돌아오는 순서다. 후속 요청에 따라 회색 벽과 바닥 표현을 없애고 흰색 캔버스로 바꿨다.
- 인사기본과 명세서는 작은 프레임, 조직도는 넓은 프레임, 물결은 정면의 큰 프레임으로 구분한다.
- 세로로 긴 데스크톱 창에서는 화면 비율에 따라 전체 보기 카메라를 뒤로 이동해 앞쪽 프레임이 잘리지 않도록 한다.
- 문구는 VIBE-HR 로고 옆으로 옮겼다. 64px 헤더 아래의 남은 화면을 모두 갤러리로 사용하며 탐색 안내와 조작 버튼은 캔버스 위에 배치한다. 모바일 목록에서는 문구를 로고 아래에 배치해 가독성을 유지한다.
- 휠과 트랙패드는 장면 순서를 이동한다. 시작과 끝에서는 일반 페이지 스크롤로 이어진다.
- 왼쪽 버튼 드래그는 제한된 좌우 및 상하 시점 이동이다. 6px를 넘긴 드래그는 클릭으로 처리하지 않는다. 전체 공간 보기는 시점을 초기화한다.
- 실제 화면 프레임 클릭과 화면 확대 버튼은 같은 상세 보기를 연다. 이전/다음, 방향키, Enter, Escape와 포커스 복귀를 지원한다.
- 모바일, 모션 감소 설정, WebGL 초기화 실패와 컨텍스트 손실은 동일한 17장면 세로 목록을 제공한다. 확대 화면은 작은 기기에서도 본문을 가로로 이동해 읽을 수 있다.
- 기존 물결은 갤러리에서 원본 포스터로 보인다. 후속 요청을 반영해 클릭으로 확대하면 기존 `createConservatoryScene`이 자동 재생된다. 정지와 재생 버튼은 유지하며 상세 보기를 닫으면 렌더러를 해제한다. 모션 감소 설정에서는 렌더러를 불러오지 않고 정지 화면을 유지한다.

## 화면 자료

현재 내부 애플리케이션을 독립적인 합성 데이터 서버로 실행해 업무 본문을 준비했다. 이름, 인원, 날짜, 금액은 시연용이며 실제 직원 정보는 포함하지 않는다. 로그인 사용자 메뉴, 세션 시간과 브라우저 주소는 포함하지 않는다.

초기 제품 화면16개는 WebP 정지 이미지로 구성했다. 후속 요청으로 실제 UI 상태65개를 연결한 웹 모션을 적용했고, 선택한 장면만 재생한다. 자세한 흐름과 검증은 `2026-10-18-product-scene-motion.md`에 기록했다. 별도 영상 파일을16개 재생하는 방식은 아니다. 시연 속 저장과 승인 버튼은 실제 업무 요청을 실행하지 않는다.

사원관리와 인사 이력은 저장 전 변경 표시가 보이는 상태다. 결재는 문서를 선택한 상태, 명세서는 상세 문서, 전표와 퇴직금은 상세 근거 중심으로 구성했다. 각 화면의 밝음/어두움 및 강조색은 승인한 장면표를 따른다.

출처, 경로, 테마, 합성 데이터 여부, 파일 해시와 업무 쓰기 0건 확인은 `frontend/public/images/product/provenance.json`에 기록한다. 새 외부 이미지나 의존성을 추가하지 않았다.

## 성능과 단순화

- Three.js는 데스크톱 공간 모드에서 지연 로딩한다. 서버 HTML에는 제품 설명과 전체 장면 목록이 들어간다.
- 제품 그리드16개나 iframe을 동시에 실행하지 않는다. 전체 보기에는 포스터를 사용하고 선택한 제품 프레임만 CanvasTexture로 갱신한다. 포스터 동시 로딩은3개로 제한하며 시연 상태는 현재 장면의4~5개 이미지만 요청한다.
- 정적인 전체 보기에서는 카메라가 안정되면 프레임 요청을 멈춘다. 시연 중에는 해당 프레임만 최대30fps로 갱신하며 숨겨진 탭과 확대 중에는 배경 재생을 멈춘다.
- 화면 전환, 모바일 전환, 모션 감소 설정과 언마운트 시 텍스처, geometry, material, observer, event listener, WebGL 렌더러를 정리한다.
- 물결은 확대 시 자동 재생하고 기존 장면 품질 조절기를 재사용한다. 제품 시연과 물결이 동시에 재생되지 않도록 한다.

고유 브라우저 시나리오는 72개다. 최종 smoke 2개는 기존 58개에 포함되므로 중복 합산하지 않는다. 자료 생성 검사 16개와 수동 production 확인도 이 숫자에 섞지 않는다.

실제 브라우저에서 390px, 768px, 1175px, 1440px, 1920px를 확인했다. 1175px는 세로로 긴 앱 미리보기 창의 구도 보정용이다. 모든 제품 장면을 실제 UI 이미지로 검토했고, 로딩 상태였던 초안 자료는 완료 상태로 교체했다. 의도적인 WebGL 실패 검사와 원래 물결 shader의 드라이버 정밀도 경고는 예상 로그이며 실제 production 확인에서는 페이지 오류가 없었다.

`http://127.0.0.1:3102/`는 합성 데이터 전용 로컬 미리보기다. production Next 서버, 합성 서비스와 loopback 중계만 사용한다. 중계는 기존 BFF의 신뢰 IP 헤더 요구를 충족하며 인증 코드를 우회하거나 변경하지 않는다. 임시 비밀값은 프로세스 환경에만 두고 파일과 로그에 저장하지 않는다. 소유 프로세스는 `preview-processes.json`에 기록했다.

production 측정은 `production-verification.json`, 현재 코드 해시는 `source-snapshot.json`, 종합 결과는 `verification.json`에 있다. 이미지 합계는 전체 첫 다운로드 용량을 뜻하지 않는다. 기존 전체 한글 Pretendard 폰트 약 2.06MB와 JavaScript가 별도로 포함되며 실제 전송값도 측정 파일에 남긴다. 로컬 프레임 측정은 해당 Chromium/D3D11 환경의 관측치다.

운영 배포나 실제 업무 데이터 쓰기는 수행하지 않는다. 로컬 합성 서비스 검사는 운영 인증과 모든 실제 GPU/브라우저 조합을 인증하는 검사가 아니다. 내부 제품 디자인이 바뀌면 합성 자료를 재생성해야 한다.

## 후속 수정: 물결 자동 재생

사용자가 가운데 장면 클릭만으로 물결을 재생하도록 요청했다. `water-exhibit.tsx`의 초기 재생 상태를 모션 감소 설정에 따라 결정하도록 바꿨다. 확대 시 자동 시작하고, 정지 후 닫았다가 다시 열어도 자동 시작한다. 별도 최초 재생 클릭을 없앴으며 정지와 재생, 실패 시 정적 배경, 닫기 시 자원 해제는 유지한다.

후속 검증은 전체 lint, 단위 테스트312개, 랜딩 브라우저14개, grid registry와 production build/TypeScript가 모두 통과했다. 모션 감소 설정에서 텍스처 요청 없이 정적 화면을 유지하는 검사를 추가했다. 이전58개 업무 회귀 및 원본 GPU 검사는 변경 없는 소스의 기존 결과를 유지한다. 누적 고유 브라우저 시나리오는73개다.

production에서도 중앙 프레임을 직접 클릭해 재생 버튼 없이 시작하고 장면 정지가 표시되는지 확인했다. 페이지 오류는0건이며 증거는 `water-autoplay-verification.json`과 `water-autoplay.png`다. 미리보기 서버는 갱신했으나 앱 브라우저의 탭 새로고침은 URL 접근 정책에서 차단되어 우회하지 않았다. 열려 있던 탭은 사용자가 한 번 새로고침하면 된다.

## 후속 수정: 화면 전체를 사용하는 흰색 캔버스

큰 소개 제목과 설명 영역을 없애고 `사람과 일, 하나의 흐름으로.`를 VIBE-HR 로고 옆에 배치했다. 데스크톱은64px 헤더 아래를 모두 갤러리로 사용한다. 탐색 안내, 현재 장면, 이동/확대/초기화 버튼과 합성 데이터 안내는 캔버스 위에 얹는다. 별도 하단 영역과 공간 안의 중복 로고도 없앴다.

화면과 Three.js 배경을 흰색으로 통일했다. 회색 바닥과 벽 mesh4개, 안개 효과를 제거했고 작품 프레임은 더 얇게 정리했다. 공간 배치, 카메라 탐색, 확대, 키보드 접근, 물결 자동 재생과 원본 배경은 유지한다. 모바일과 모션 감소 목록은 일반 문서 스크롤을 유지하며 좁은 헤더에서는 문구를 로고 아래에 배치한다.

1440x1000 기준 갤러리 높이는520px에서936px로 늘었다.900x720,1440x1000,1175x1252에서 실제 캔버스 픽셀이 흰색인지, 로고 옆 제목이 정렬되는지, 페이지 넘침과 버튼 가림이 없는지 검사했다. 랜딩17개 검사와 `check:ui`의 전체 lint, 단위 테스트312개, 기존 UI smoke2개, grid registry, production build/TypeScript가 모두 통과했다. 기존에 실행한 변경 없는 업무58개와 원본 GPU1개를 포함한 누적 고유 브라우저 사례는76개이며 이번 실행 수와 구분한다.

production 결과는 `white-gallery-verification.json`, 전체 구도는 `white-gallery-production.png`, 사원관리 접근 구도는 `white-gallery-selected.png`다. 실제 빌드에서 페이지 오류와 갤러리 API 호출이 없고 로컬 미리보기 서버를 새 빌드로 갱신했다. 로그인 화면과 운영 환경은 변경하지 않았다.
