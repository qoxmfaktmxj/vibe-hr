# 갤러리 이동과 커서 개선

## 확인한 차이

사용자가 표시한 파란 띠는 클릭 후 canvas 전체에 표시되던 포커스 outline이었다. 기존 커서는 grab/grabbing으로 바뀌었다. 카메라 위치에는 보간이 있었으나 드래그 회전값은 바로 적용했고, 장면 이동 시 회전값을 즉시 초기화했다.

[Alim Designer](https://alimdesigner.com/)에서 실제 스크롤과 좌클릭 드래그를 실행하고 초기/이동 중/정착 화면을 비교했다. REA로 동일 페이지의 공개 스크립트를 관찰해 데스크톱 목표 회전 감쇠와 장면 이동 시 작은 후퇴가 있음을 확인했다. 페이지의 모바일 일렬 배치는 현재 VIBE-HR의 모바일 목록과 별개이며 그대로 옮기지 않았다.

REA evidence: `ev_297eb50c7c4f9a24278d09ee824764f580310bdf27e32ad19da0eb4dcb2b4fc1`. 관찰한 페이지 스크립트 SHA-256: `d84cf5010d1e1f9a0c1fbc1f1b26a603968fcad4dd3396d9f0222cba988b5853`. 같은 origin의 공개 스크립트와 조작 화면만 근거로 삼았으며 외부 예약 iframe과 이전 네트워크 활동은 분석 범위가 아니다. 참고 사이트의 미디어, 이름표와 구현 코드는 복제하지 않았다.

## 반영 내용

- canvas 외곽 포커스 띠를 없앤다. 키보드 탐색 시 조작 안내에만 작은 포커스 표시를 남긴다.
- 기존 VIBE 코발트색의 SVG 화살표를 브라우저 기본 커서 방식으로 사용한다. 드래그 시에도 같은 화살표이며 이름표는 없다.
- 작은 휠 입력을 누적하고 짧은 버퍼를 거쳐 이동한다. 가로 트랙패드 입력도 지원하며 확대 제스처는 가로채지 않는다.
- 위치와 회전 목표를 시간 기준 감쇠로 따라간다. 드래그를 놓아도 남은 간격을 부드럽게 줄이고 완전히 정착한다.
- 장면 이동 시0.55 공간 단위의 작은 후퇴를 약1.05초에 걸쳐 넣는다. 기존 흰 공간, 프레임 배치,17장면과 클릭 확대는 유지한다.
- 새 라이브러리나 매 프레임 React 상태 갱신을 추가하지 않는다. 대기 중인 휠 입력은 직접 드래그, 키보드, 장면 바로가기, 확대와 해제 시 취소한다.
- 후속 요청에 따라 선택 화면에1.5px 코발트 테두리와 네 개의7px 사각 표시를 추가했다. 실제3D 꼭짓점을 화면 좌표로 투영하여 기울기, 카메라 이동과 크기 변경을 따라간다. SVG는 포인터 입력과 키보드 초점을 받지 않으며 좌표가 같을 때 DOM을 갱신하지 않는다.

## 파일과 검증

변경 파일은 `frontend/src/components/landing/gallery-canvas.tsx`, `gallery-world.ts`, `landing.module.css`, `frontend/public/brand/gallery-cursor.svg`, `frontend/tests/e2e/product-landing.spec.ts`다.

추가 검사는 마우스/키보드 포커스 구분, 드래그 중 화살표 유지, 손을 놓은 뒤 이동과 정착, 작은 휠 입력의 누적, 처음 장면 경계, 가로 휠과 Ctrl+휠을 확인한다. 선택 테두리는 네 사각 표시와 꼭짓점의 오차, 원근 이동, 전체 공간 복귀 시 숨김, 클릭 확대와 반응형 해제를 검사한다. 기존17장면 접근, 클릭/드래그 구분, 키보드 이동, 확대, 반응형과 단독 재생 검사도 유지한다.

최종 결과와 production build 확인은 `docs/TASK_LEDGER.md`와 `frontend/output/gallery-interaction-20261019/outline-verification.json`에 기록한다. `verification.json`은 테두리 추가 전 커서/감쇠 변경의 검증이다. 참고 화면과 로컬 검증 이미지는 같은 로컬 증거 폴더 및 기존 랜딩 캡처 폴더에 보존한다. 2026-10-21 사용자가 푸시를 요청했다. Git 게시와 자동 배포 완료는 구분하여 확인한다.
