# VIBE-HR 내부 화면 전수 점검과 리디자인 제안

작성: 2026-10-18, Asia/Seoul
상태: 검토용 개선안. 제품 코드, 공통 그리드, 권한, DB, 배포 변경 없음.
소스 기준: `9b4ab8fc8bbb62f6fcfd3d7dfa0b3a013095c62f`
현재 작업 위험도: R0. 추후 공통 그리드와 메뉴 구성 구현은 R2 범위 검토 필요.

## 제안의 중심

**하나의 시각 체계와 여섯 가지 업무 구도**를 권장한다. 대량 조회와 편집은 AG Grid를 중심에 놓고, 결재와 개인 신청, 인사 상세, 조직도, 권한 설정은 각 업무를 이해하기 좋은 구도를 사용한다.

현재 문제는 단순히 스타일이 오래된 데 있지 않다. 같은 조회와 저장이 화면마다 다른 위치와 순서로 나타나고, 정보량과 관계없이 큰 카드와 입력 폼이 반복되며, 표준 검사가 실제 UI 사용을 보장하지 못하는 것이 더 크다. 먼저 이 차이를 정리한 뒤 타이포그래피, 여백, 색, 아이콘을 바꾸는 편이 효과적이다.

앞서 계획한 공개 3D 갤러리와 내부 업무 화면은 역할을 구분한다. 내부는 읽기와 작업에 집중하고, 완성된 내부 화면을 나중에 17개 갤러리 장면에 넣는다. 기존 물결 배경과 로그인은 보존한다. 이번에는 갤러리용 촬영이나 영상 제작을 하지 않았다.

브라우저 조사는 레이아웃 조사이며 모든 저장, 승인, 급여 계산을 실행한 기능 검증이 아니다. 실제 운영 배포의 SHA는 별도로 확인하지 않았으므로 소스 SHA와 배포가 동일하다고 단정하지 않는다. 일부 목록은 첫 진입 로딩 상태였고, 인사 이력 일부는 추가 관찰에서도 로딩 표시가 남았다. 해당 화면의 최종 데이터 상태는 미검증으로 기록한다.

## 3. 그리드 준수 여부에 대한 판단

### A. 실제 AG Grid 표준 편차

등록된 AG Grid 69개 경로에서 미등록 경로는 발견하지 않았다. 하지만 `npm run validate:grid` 통과는 시각과 행동의 완전한 일치를 의미하지 않는다.

- 검사기는 공통 이름이 문자열로 들어 있는지 확인하는 구간이 있다. `void GridToolbarActions`도 존재 검사에 포함될 수 있다.
- 실제 도구의 순서, 화면에 렌더링된 컨트롤, 모든 중첩 표의 공통 사용을 전부 검사하지 않는다.
- `totalCount`와 `pageSize` 이름이 함께 있을 때만 페이지 이동 관련 검사가 작동하는 조건이 있다.
- readonly/workflow/approval 변형의 예외를 코드 검사, 등록부, 표준 문서가 같은 의미로 설명해야 한다.

따라서 리디자인 첫 단계는 새 스타일의 적용보다 **공통 그리드 계약과 예외 목록을 정합하게 만드는 것**이다. 단, 이번 요청에서는 코드나 표준을 변경하지 않는다.

### B. 확정한 HTML 표 전환 범위

사용자 결정에 따라 관리 목록은 그리드를 기본으로 하고, 수정 내용은 저장 버튼을 눌러야 일괄 반영하도록 설계한다. 14개 파일의 네이티브 table 선언 19개를 빠짐없이 분류했다.

| 분류 | 수 | 주요 대상 |
| --- | ---: | --- |
| 편집형 그리드 | 6 | 신청서 코드, 결재선 템플릿, 조직 근무 배정, 개인 예외, 인사기본의 발령/기타 이력 템플릿 |
| 읽기 전용/업무 동작형 그리드 | 5 | 급여월 목록, 퇴직 임금 산입 근거, 전표 라인, 내 휴가 목록, 월마감 |
| 전용 표현 예외 | 7 | 사원 피벗, 명세서 수당/공제, 퇴직세 요약, 대상자 스냅샷, 메뉴/액션 권한 매트릭스 |
| 현재 미연결 | 1 | 이전 퇴직관리 체크리스트 컴포넌트 |

편집형은 추가/수정/삭제를 임시 상태로 보관하고 활성 편집 영역 단위로 저장한다. 승인/반려, 신청 제출/취소, 마감/재오픈은 별도 업무 버튼으로 유지한다. 읽기 전용에는 일반 저장 버튼을 표시하지 않는다.

### C. 예외의 기준

여러 레코드를 탐색하거나 관리하는 목록은 그리드 전환 대상이다. 개인 명세서의 문서 표현, 단일 대상의 라벨/값, 권한 교차 매트릭스는 전용 표현을 유지한다. 권한 매트릭스처럼 편집 가능한 예외도 명시적 저장 원칙을 따른다.

조직도와 메뉴 편집의 트리, 출퇴근/신청 폼은 표 전환과 별개로 업무 구도를 유지한다. 월마감은 현재 custom 등록이지만 목표 설계에서는 읽기 전용 그리드와 기존 업무 버튼으로 전환한다.

개별 소스 위치, 저장 단위, API 선행 조건과 모든 예외는 [HTML 표 전환과 공통 저장 설계](2026-10-18-grid-save-contract.md)를 기준으로 한다. 이번 반영은 설계 결정이며 변환 코드는 아직 적용하지 않았다.

## 4. 권장 디자인 방향

### 업무 공간

- 밝은 본문과 차분한 중립색 탐색 영역을 기본으로 한다. 브랜드 강조색은 선택, 주요 동작, 초점에 집중한다.
- 현재 두 겹의 왼쪽 탐색을 한 개의 가변 폭 탐색 영역으로 통합하는 안을 우선 검토한다. 도메인과 하위 메뉴 관계, 기존 빠른 이동, 열린 탭은 유지할 수 있다.
- 비교 대안은 현재의 레일을 유지하되 보조 메뉴가 필요할 때만 펼치는 방식이다. 통합형은 본문 폭이 넓어지고, 레일 유지형은 기존 사용자 적응 비용이 낮다. 대표 업무 3개로 비교한 후 선택한다.
- 제목은 화면당 한 번 크게 표시하고, 경로/보조 설명/탭은 낮은 위계를 가진다.
- 입력 컨트롤은 사각형에 가까운 작은 라운드를 사용하고, pill은 필터 값과 상태 등 묶음을 표현할 때로 제한한다.
- 검색, 표 도구, 데이터가 하나의 작업 면으로 읽히도록 큰 카드 중첩과 두꺼운 여백을 줄인다.

| 주요 입력 높이 | 약 36px | 검색과 폼의 리듬 통일 |
| 모바일 조작 | 터치 영역 44px 이상을 목표 | 작은 아이콘의 실제 누르기 영역 확보 |

수치는 설계 시작점이며 확정된 디자인 토큰이 아니다. 1440px, 1280px, 1024px, 390px와 긴 한글 이름, 큰 금액, 다수 탭을 넣어 검토한다.

## 5. 여섯 가지 업무 구도

| 구도 | 구성 | 적용 대상과 중요한 차이 |
| --- | --- | --- |
| 1. 목록과 일괄 편집 | 제목 → 핵심 조건 → 추가 조건 → 페이지/건수/변경 요약 + 표준 도구 → AG Grid | 사원, 코드, 급여 기준, 평가 기준, 이력 관리. 선택/편집/변경/저장 상태를 명확히 유지 |
| 2. 목록과 상세 | 선택 목록 + 오른쪽 상세, 좁은 폭에서는 상세 화면으로 전환 | MNG 관리, 인사 발령, 조직개편, 공통코드, 급여 Run. 상단에 빈 편집 폼을 항상 펼쳐두지 않음 |
| 3. 신청과 결재 | 상태별 목록 + 선택 요청 내용 + 처리 동작 | 내 신청서, 결재함, 수신함, 교육 승인, 복리후생. CRUD 도구 대신 실제 허용된 업무 동작 |
| 4. 개인 서비스와 정보 | 핵심 요약 + 섹션형 정보/폼 + 명확한 완료 상태 | 인사기본, 출퇴근, 휴가 신청, 내 급여조회. HR 담당자용 대량 편집 화면과 동일한 밀도를 강요하지 않음 |
| 5. 업무 홈과 현황 | 우선 처리할 일 + 주요 현황 + 추이 | 대시보드, 근태 리포트, 복리후생 요약. 현재 API로 확인 가능한 지표만 표시 |
| 6. 구조와 설정 | 트리/매트릭스/설정 섹션 + 선택 항목 편집 | 조직도, 메뉴, 권한, 역할, 시스템 설정. 관계를 드러내고 위험 동작은 일반 저장과 구분 |

동일한 것: 글꼴, 표면색, 선, 버튼, 아이콘, 검색 문구, 선택/오류/저장 피드백, 간격 체계.
달라야 하는 것: 정보 배치, 편집 단위, 행 선택 후 행동, 상세를 보여주는 방식, 데이터 밀도.

표준 액션 순서를 시안에서도 유지한다. 저장을 마지막에 두는 새 규칙을 조용히 만들지 않는다. 권한 모델과 서버 검증은 유지하고, 메뉴 구조 변경 시 `MENU_ACTION_PERMISSION_PLAN.md`와 함께 검토한다.

## 8. 폰트와 아이콘

### 폰트

현재의 Pretendard를 기본 후보로 유지하고, 글꼴을 바꾸기 전에 크기, 굵기, 행간, 숫자 정렬을 먼저 정리하는 안을 권장한다. 대안은 SUIT로 실제 한글 업무 문장과 숫자를 비교한 후 결정한다.

[Best Free Fonts의 Geist](https://bestfreefonts.com/geist)와 [Instrument Sans](https://bestfreefonts.com/instrument-sans)는 살펴본 상세 페이지에 Latin 지원으로 안내돼 있다. 따라서 이것만으로 한국어 본문 전체를 교체하는 안은 적절하지 않다. 영문 브랜드나 숫자 일부에 사용하려면 한글 fallback과 혼합 문장의 기준선을 확인해야 한다. 현재 단계에서 폰트를 설치하거나 추가하지 않는다.

원 제작 자료: [Pretendard](https://github.com/orioncactus/pretendard), [SUIT](https://github.com/sun-typeface/SUIT). 사용 버전의 글리프, 라이선스, 웹폰트 용량은 최종 채택 시 다시 확인한다.

### 아이콘

[21st.dev 아이콘](https://21st.dev/community/icons)의 로그인된 화면에서 Hugeicons, Lucide, Tabler의 People 분류를 비교했다. 복사 버튼을 누르거나 무료 복사 횟수를 소모하지 않았다.

| 후보 | VIBE-HR에서의 판단 |
| --- | --- |
| Lucide | 현재 컴포넌트와 메뉴 이름 계약에 이미 연결됨. 의미별 아이콘 재선정과 규격 통일을 우선 권장 |
| Hugeicons | 인물/직무 표현이 풍부함. 브랜드 변화가 더 필요할 때 전체 계열 교체 후보로 검토 |
| Tabler | 표와 도구에 적합한 가는 외곽선 체계. 작은 크기의 구별성과 현행 아이콘 이름 매핑을 함께 검토 |

세 계열을 화면마다 섞지 않는다. 기본 제안은 메뉴 18~20px, 도구 16px, 공통 stroke 규격이다. 선택 상태는 아이콘 색뿐 아니라 배경과 텍스트로도 표시한다. 검색, 저장, 다운로드처럼 반복되는 동작은 같은 아이콘을 쓴다. 행마다 움직이는 아이콘은 추가하지 않는다.

현재 `menu-icon-render.tsx`는 Lucide 이름을 해석하고 `GridToolbarAction`은 LucideIcon 타입을 사용한다. 따라서 계열 교체는 단순 파일 교체가 아니라 메뉴 설정과 공통 도구의 호환성을 확인해야 하는 선택이다.

## 9. 적용 순서

1. **기준 정합성과 표시 결함:** 상태 문자열 노출, 표준 도구 순서, 실제 공통 JSX 사용, 예외 등록을 먼저 정리한다.
2. **공통 시안 3개:** 사원관리, 결재 목록과 상세, 인사기본으로 밀도와 정보 위계를 비교한다. 가장 보기 좋은 화면 하나만으로 전체 디자인을 확정하지 않는다.
3. **공통 작업 면:** 탐색, 타이포그래피, 검색, 버튼, 상태, 그리드 헤더/행을 정리한다.
4. **한 유형씩 확장:** 공통 CRUD → 조회형 → 선택 상세/업무 흐름 → 개인 서비스 → 구조/설정 순서로 적용한다.
5. **도메인 회귀:** 91개 경로 목록을 다시 대조하고, 데이터 있음/없음/로딩/실패/선택/편집/저장 상태를 확인한다.
6. **공개 갤러리 소재:** 내부 디자인 기준이 확정된 후 기존 17장면 구도에 실제 화면을 넣는다.

첫 구현 범위의 권장안은 공통 셸, 공통 그리드, 사원관리, 결재함, 인사기본이다. 그리드 공통부는 R2 승인이 필요한 범위다. 권한과 인증, 급여 의미, DB 변경을 이 디자인 작업에 끼워 넣지 않는다. 현재는 구현 승인을 요청하는 단계가 아니라 근거와 선택지를 검토하는 단계다.

## 10. 완료 판정 기준과 이번 조사 한계

- 구현 후 모든 등록 화면에서 표준 버튼 순서, 페이지 이동/건수 위치, 열 헤더와 행 상태가 일치해야 한다.
- 별도 HTML 표는 예외 이유와 소유 화면이 기록돼야 한다.
- 390px에서 첫 데이터나 핵심 작업까지 불필요한 컨트롤을 여러 화면 높이만큼 지나지 않아야 한다.
- 밝음과 어두움에서 선택/초점/실패/저장이 구별돼야 한다. 색 대비 수치 검증은 이번 관찰만으로 통과 처리하지 않는다.
- 메뉴와 액션의 허용/거부 회귀, 기존 데이터 편집/붙여넣기/취소/미저장 이동 보호를 유지해야 한다.
- `npm run validate:grid`는 이번에 통과했다. `impeccable detect --json frontend/src/components`는 빈 배열을 반환했지만, 실제 화면에서 관찰한 편차와 결함이 있으므로 디자인 통과 판정으로 사용하지 않는다.
- 이번에는 제품 코드 변경이 없어 lint/build/저장 동작 테스트를 실행하지 않았다.
- 원인 미확정 로딩 지속, 배포 SHA 미확인, 모든 서브탭/팝업 미검토, 역할별 상태 미검토는 남은 범위다. 전체 첫 화면 확인과 모든 상호작용 검증을 구분한다.

전체 경로별 판정과 참고 링크는 같은 폴더의 `2026-10-18-screen-coverage.md`, `2026-10-18-reference-register.md`에 기록한다. 시각적 확인 자료는 `output/design-audit-20261018/review.html`에서 탐색할 수 있다.
