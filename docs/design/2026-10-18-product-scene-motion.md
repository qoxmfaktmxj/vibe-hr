# 제품 장면 모션 구현

날짜: 2026-10-18
상태: 구현과 로컬 검증 완료. 커밋, 푸시, 운영 배포는 수행하지 않았다.

## 범위와 표현 방식

사용자는 각 제품 화면이 레퍼런스처럼 움직이고 조회, 수정, 저장 과정이 보이며 보고 있는 장면만 재생되도록 요청했다. 기존 흰색 갤러리,17장면, 로그인 진입과 물결 자동 재생은 유지했다.

실제 애플리케이션을 합성 데이터로 실행해16개 제품 장면의65개 UI 상태를 준비했다. 이 상태들 사이의 전환과 커서 이동, 클릭 반응, 단계 안내를 브라우저 Canvas에서 재생한다. 별도 영상 파일이나 라이브 업무 iframe을16개 실행하지 않는다. Three.js 안의 선택 프레임과 확대 화면, 모바일 목록이 같은 재생기를 사용한다.

이미지 합계는2,179,158바이트다. 현재 장면의 작은 manifest와4~5개 상태 이미지만 가져온다. 기존 전체 보기의 포스터는 그대로 유지하며 초기 진입에는 모션 상태 파일을 요청하지 않는다. 다른 장면으로 바꾸면 이전 요청을 취소하고 디코딩된 이미지를 해제한다.16개 원본 포스터와 기존 물결 장면은 변경하지 않았다.

편집 화면은 저장 전 초안과 저장 후 결과를 모두 보여준다. 조회 전용 화면에 가짜 저장을 넣지 않았으며 승인과 마감은 실제 화면에 있는 별도 확인 절차를 사용했다. 준비 과정의 쓰기는 모두 loopback 합성 서비스 또는 브라우저의 상태 저장 fixture에서 처리했다. 공개 랜딩은 업무 API를 호출하지 않는다.

## 재생 규칙

- 전체 보기에서는 포스터만 표시한다.
- 스크롤이나 선택으로 접근한 제품 프레임 하나만 재생한다. 드래그로 선택 프레임 중심이 시야를 벗어나면 멈춘다.
- 확대 화면을 열면 배경 프레임은 멈추고 확대된 장면만 재생한다. 확대에서는 흐름을 처음부터 읽을 수 있도록 시작한다.
- 목록은 화면에 가장 많이 보이는 항목 하나를 고른다. 확대 중에는 목록 재생기를 제거한다.
- 물결을 열면 제품 시연은 멈추고 기존 물결만 재생된다.
- 시연 일시 정지/재생은 공간과 확대 화면에서 사용할 수 있다. 물결의 기존 정지 버튼도 유지한다.
- 숨겨진 탭과 화면 밖 재생기는 시간을 진행시키지 않는다. 모션 감소 설정에서는 상태 이미지를 내려받지 않고 기존 포스터를 표시한다.
- 상태 이미지 로딩 실패는 포스터로 대체한다. 다시 열거나 일시 정지 후 재생하면 재시도할 수 있다.
- 이미지, abort controller, observer, 이벤트와 프레임 요청은 전환/해제 시 정리한다. 재생은 최대30fps이며 한 주기는7.2~9초다.

단계 안내는 다음 상태가 완전히 나타난 뒤 갱신해, 화면이 아직 수정 중인데 저장 완료라고 먼저 표시하지 않도록 했다.

## 함께 수정한 실제 화면 문제

인사 이력에서 동일한 응답으로 재조회한 뒤 수정하면 행이 사라졌다. 재조회가 `rowsRef`를 빈 배열로 만들지만 SWR은 동일 데이터의 객체를 유지하므로 이후 동기화 effect가 실행되지 않았다. 다음 셀 편집이 빈 배열을 기준으로 작업하는 것이 원인이었다.

`hr-basic-tabs.tsx`의 reset에서 현재 원본 행으로 ref를 초기화하도록 한 줄 수정했다. 시연 준비에서 두 번 재현했고, 실패 trace를 보존했다. 별도 회귀 사례는 동일 결과 재조회 후 수정과 저장, 기존 다른 행 유지, 정확한 batch 내용을 확인한다. 공유 그리드 규칙이나 API는 바꾸지 않았다.

이번 검증의 고유 브라우저 사례는46개다. 모션 단계 안내를 실제 표시 상태에 맞춘 뒤 픽셀 비교 검사의 추가1초 대기가 다음 루프까지 넘어간 것을 발견했다. 표시된 저장 단계에서 즉시 정지하고 같은 단계임을 확인하도록 검사 타이밍을 수정했다. 해당 전체 사례를2회 반복 통과했으며 나머지7개 모션 사례는 같은 제품 코드로 통과한 결과를 유지한다. 실패와 수정 근거는 `motion-timing-test-correction.json`에 기록했다.

최종 production build ID는`I-wIttYCwnDt4KmK7vsIA`다. `motion-verification.json`에 환경과 검사 수를 기록했고, `employee-workflow-proof.webm`은 실제 재생 중인 사원관리 Canvas를 기록한 약8.8초 확인 영상이다. 앱의 재생 매체는 영상 파일이 아니라 앞서 설명한 UI 상태 기반 Canvas다. 새 빌드로 loopback 미리보기 서버를 갱신했다.

합성 UI 상태로 만든 시연 모션이며 실시간 업무 입력창은 아니다. 실제 제품 디자인이 바뀌면 자료를 다시 준비해야 한다. 운영 배포와 실제 데이터 쓰기는 수행하지 않는다.

기존 복리후생 확인창은 합성 자료 준비 중 중첩 paragraph 마크업 경고를 출력했다. 처리와 결과 검증은 통과했고, 이 기존 경고는 랜딩에 전달되지 않는다. 관련 없는 공통 dialog 리팩터링은 이번 변경에 포함하지 않았다.
