# 사이드바 닫기 위치 비교

날짜: 2026-10-18
상태: 사용자가 B안을 승인하여 로컬 제품 코드에 적용했다. 이어 선택 표현도 테마색과 Bold로 통일했다.

## 확정 B안: 세부 메뉴 헤더에서 닫기

1. 로고 아래에 있던 독립 화살표 줄을 제거한다.
2. 세부 메뉴 제목 오른쪽에 32px의 작은 닫기 버튼을 둔다. 메뉴 그룹 전체 펼치기/접기는 별도 아이콘과 접근성 이름으로 구분한다.
3. 닫으면 72px 대메뉴 레일만 남는다. 마지막 선택한 업무와 열린 하위 그룹 상태는 보존한다.
4. 대메뉴를 누르면 해당 세부 메뉴가 다시 열린다. 이미 선택된 대메뉴를 다시 눌러도 열리게 한다.
5. 마우스를 스치기만 해도 자동으로 열리는 동작은 넣지 않는다. 클릭과 키보드 Enter/Space로 연다.
6. 닫기 버튼이 사라질 때 키보드 초점은 현재 대메뉴로 돌려준다. 접힌 영역은 기존 inert 정책을 유지한다.

이 안은 레일에 업무 메뉴만 남겨 사진에서 지적한 빈 줄을 없앤다. 열기와 닫기의 위치가 달라지므로 대메뉴의 접근성 이름/expanded 상태와 간단한 도움말로 다시 열 수 있음을 명확히 한다. 화면이 좁을 때는 기존 모바일 메뉴 열기/닫기 흐름을 유지한다.

## 대안: 현재 버튼을 24~28px로 축소

같은 위치에서 열고 닫을 수 있어 기존 사용법이 유지된다. 다만 로고와 첫 업무 메뉴 사이에 별도 제어 줄이 계속 남는다. 시각적으로 지적한 부분을 줄일 수는 있지만 제거하지는 못한다.

| 기준 | 레일 작은 토글 | 헤더 닫기 + 대메뉴로 열기 |
| --- | --- | --- |
| 레일의 빈 제어 줄 | 남음 | 제거 |
| 조작 위치 | 한 위치 | 닫기는 헤더, 열기는 대메뉴 |
| 업무 메뉴의 시작 위치 | 토글 아래 | 로고 바로 아래 |
| 구현 범위 | 크기 변경 중심 | 위치, 상태 설명, 초점 복귀 확인 |
| 추천 | 대안 | 우선 추천 |

## 참고 근거

- [shadcn Sidebar 문서](https://ui.shadcn.com/docs/components/radix/sidebar): 접기 동작과 트리거 위치를 분리할 수 있다. 별도의 두꺼운 토글 공간을 반드시 둘 필요는 없다.
- [shadcn Sidebar Blocks](https://ui.shadcn.com/blocks/sidebar): 아이콘으로 접는 구성과 보조 탐색을 가진 inset 구성을 비교할 수 있다. 현재 VIBE-HR에는 새 라이브러리 도입 없이 배치 원리만 참고한다.
- [Linear의 사이드바 접기 소개](https://linear.app/changelog/unpublished-collapsible-sidebar): 경계 클릭과 단축키, 상단 아이콘 등 조작 진입점을 설명한다. 2023년 자료이므로 현재 Linear의 모든 화면 동작을 보증하는 근거로 쓰지 않는다.
- UIBOWL에서 피처링과 Mixpanel의 사이드 탐색 대표 화면을 추가로 확인했다. 조밀한 탐색 배치는 참고할 수 있지만, 정적 이미지로 접기 동작 자체를 확인한 것은 아니다.

추천안은 위 사례를 바탕으로 VIBE-HR의 고정 대메뉴 레일에 맞춰 제안한 것이다. 참고 사이트와 동작이 완전히 같다는 의미는 아니다.

비교용 HTML: `frontend/output/common-design-20261018/sidebar-options.html`. 이 파일은 결정 당시의 A/B 비교 기록이며 제품에는 연결되지 않는다. 최신 선택 표현과 B안은 실제 사이드바와 `frontend/output/common-design-20261018/preview.html`의 세 화면 비교에 반영한다.

## 선택 표현

- 선택 메뉴명은 테마색과 굵기 700으로 표시한다. 아이콘도 같은 색을 사용하고 크기와 선 굵기는 유지한다.
- 대메뉴와 세부 메뉴의 선택 배경, 왼쪽 강조선, 선택 외곽선을 제거한다.
- 어두운 레일에서는 밝은 테마색을 사용하고 세부 메뉴에서는 강한 글자색과 섞어 대비를 확보한다.
- 키보드 포커스 표시는 남긴다. 일반 메뉴의 마우스 올림 피드백과 메뉴 그룹의 계층 안내는 유지한다.
