상태: 요청한 전환과 관련 검증 완료. 로컬 변경이며 커밋, 푸시, 배포는 하지 않았다.
승인: 나머지 9개 표를 같은 공통 디자인으로 전환하고 저장 버튼으로 일괄 반영하며 예외는 유지하라는 사용자 요청.
위험도: R2 공통 그리드/저장 연결. 기존 API와 DB 구조, 승인/급여/일정 생성의 업무 규칙은 유지한다.

9개 영역마다 밝음, 어두움, 모바일 캡처를 제공한다. 화면은 실제 제품 빌드로 실행했으며 데이터는 격리된 검증용 합성 데이터다. 대표적인 앞쪽 몇 개만 확인한 것이 아니라 모든 전환 대상과 별칭 경로를 검사했다.

## 저장과 공통 표현

네 편집 영역은 `BatchGridManager`를 사용한다. 추가/수정/삭제 선택은 로컬 초안이며 저장 전 서버 쓰기는 없다. 원본 값으로 복구하면 변경 표시가 해제된다. 삭제 표시는 취소할 수 있고, 실패하면 초안이 남는다. 저장 중 중복 요청과 화면 이탈을 막는다. 템플릿의 단계 변경은 부모 템플릿에 포함된다.

조직 배정과 개인 예외가 같은 페이지에 있으므로 이동 확인은 모든 편집 영역의 변경 상태를 모아서 판단한다. 한 영역을 저장해도 다른 영역의 미저장 상태는 남는다. 기존 근무코드 그리드도 같은 이동 보호에 참여한다. 일정 생성은 별도 버튼과 API를 유지한다.

조회형 그리드는 지원하는 조회와 다운로드만 표시한다. 영구 비활성 입력/복사/업로드/저장 버튼은 공통 렌더러에서 제거했다. 행 ID를 안정적으로 사용하여 고정 열의 버튼도 정확한 업무 행에 연결했다.

## 검증 중 수정한 문제

1. AG Grid 갱신 전에 삭제 체크박스가 이전 값으로 돌아가 보이던 문제를 수정했다. 클릭 상태를 즉시 표시하고 서버/그리드 값에 맞춰 정리한다. 반복 검사 3회와 조회 후 원본 복귀 검사를 통과했다.
2. 공통 읽기 전용 그리드의 자동 행 번호 대신 실제 ID를 사용한다. 고정 열의 휴가 취소와 월마감 버튼이 원하는 행을 대상으로 하는지 확인했다.
3. 복리후생 상태가 `<span ...>` 문자열로 보이던 문제를 실제 React 요소로 수정했다.
4. 기존 근태 조회가 UTC 저장 시각을 JVM 로컬 시간대로 해석하여 9시간 차이를 만들던 문제를 확인했다. `TimeGridMapper`의 `checkInAt`/`checkOutAt` 조회에 UTC 해석을 명시했다. 영향 화면은 근태 조회이며 DTO와 저장 형식, 계산 규칙과 DB 스키마는 변경하지 않았다. UTC와 Asia/Seoul에서 실제 DB 반환 시각을 검증했다.
5. 근무일정 생성의 당월 기본 날짜가 `toISOString()` 때문에 하루 앞당겨지는 문제를 수정했다. 한국 업무월의 첫날/말일을 사용하며 생성 알고리즘과 API는 유지했다. UTC 월 경계에서도 같은 기간이 표시된다.

## 단순화와 한계

네 편집 영역의 중복 상태와 저장 코드를 하나의 공통 그리드로 모았다. 조회형 세부 목록은 기존 공통 렌더러를 재사용한다. 교체된 HTML 표와 즉시 쓰기용 코드, 무의미한 비활성 도구를 제거했다. 새 의존성이나 DB 마이그레이션은 없다.

설정 목록 4개와 명세/상세 배열은 기존 전체 목록 API를 유지하고 화면에서 50행씩 나눈다. 서버 페이지 이동으로 바꿨다는 의미는 아니다. 브라우저 자체의 뒤로/앞으로 기록은 별도로 가로채지 않는다. 기존 행 잠금 외에 버전 토큰 기반 동시 편집 충돌 정책을 추가하지 않았다.

프론트와 Spring을 함께 반영해야 이전 인사 이력 batch와 이번 시각 조회 보정이 모두 적용된다. 운영 데이터와 배포에는 접근하지 않았다. 내부 표 정리 이후의 랜딩은 `2026-10-18-landing-17-scene-plan.md`에서 현재 화면을 기준으로 설계를 이어 간다. 랜딩 제품 구현과 최종 모션 자산 생성은 아직 수행하지 않았다.
