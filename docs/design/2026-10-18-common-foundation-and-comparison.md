# 공통 외곽 적용과 세 화면 비교

날짜: 2026-10-18
상태: 공통 디자인과 세 업무 화면 적용을 사용자가 승인했다. 사원관리, 결재 상세, 인사기본을 순서대로 로컬 제품 코드에 반영했다. 아래 비교 시안은 결정 당시 자료로 보존한다.
위험도: R2 공통 그리드 외곽을 포함한다. 사용자가 첨부 화면을 기준으로 사이드바, 스크롤바, 모서리 변경을 직접 요청한 범위에 한정한다.

## 적용한 기준

| 항목 | 이전 | 적용 |
| --- | --- | --- |
| 왼쪽 레일 너비 | 76px | 72px |
| 별도 접기 영역 | 24px 세로 띠 | 제거, 세부 메뉴 헤더에 32px 닫기 버튼 |
| 세부 메뉴 너비 | 208px | 208px 유지 |
| 전체 탐색 폭 | 308px | 280px |
| 영역 메뉴 높이 | 최소 76px | 최소 56px |
| 영역 메뉴 아이콘 | 20px | 18px, 기존 Lucide 유지 |
| 선택 표시 | 둥근 외곽과 곡선 인셋 | 테마색 글씨와 아이콘, 글씨 굵기 700 |
| 메뉴 모서리 | 큰 라운드 | 4px |
| 검색과 그리드 모서리 | 큰 라운드 | 6px |
| 사이드바 스크롤 | 막대 노출 | 스크롤 유지, 막대 숨김 |
| 본문 스크롤바 | 기본 또는 어두운 테마 10px | 투명 트랙과 6px |

Timeoff의 현재 브라우저 계산값에서 스크롤바 6px와 투명 트랙을 확인했다. Firefox 계열에는 표준 thin 속성이 적용되고, 정확한 6px 규격은 WebKit/Blink 스타일이다.

2단 메뉴 구조와 메뉴 권한은 유지했다. 대메뉴에 expanded와 controls 연결을 제공하고, 접힌 메뉴는 기존 inert 동작을 유지한다. 닫을 때 현재 대메뉴로 초점을 돌려주며, 같은 대메뉴나 다른 대메뉴를 누르면 다시 열린다. 긴 레일 이름은 줄바꿈 대신 한 줄로 표시하며 전체 이름은 접근성 이름과 title로 남는다.

선택 배경색, 왼쪽 강조선, 선택 외곽선은 제거한다. 키보드 포커스 표시는 유지한다. 어두운 레일은 밝은 테마색, 세부 메뉴는 배경에 대비되는 테마색을 사용한다. 일반 메뉴의 마우스 올림 피드백과 그룹 계층 안내는 유지한다.

## 추가 확정: 저장과 표 전환

편집형 관리 목록은 `셀 수정 → 변경 표시 → 저장 버튼 → 일괄 반영`으로 통일한다. HTML 표 선언 19개 중 편집형 6개와 읽기 전용/업무 동작형 5개를 그리드로 전환하고, 전용 표현 7개를 예외로 두며 미연결 1개는 보존한다.

전체 소스별 분류와 저장 단위는 [HTML 표 전환과 공통 저장 설계](2026-10-18-grid-save-contract.md)에 기록했다. 조회형 표가 그리드로 바뀌더라도 계산 결과를 편집하거나 승인/마감을 일반 저장에 섞지 않는다.

시간 연장 버튼은 빠른 이동 버튼의 `size=sm`과 동일하게 32px로 맞춘다. 6px 모서리와 기존 만료/연장 동작을 유지한다.

사이드바는 사용자가 승인한 B안을 적용했다. 레일의 독립 토글 줄을 없애고 세부 메뉴 헤더에 닫기 버튼을 두며, 대메뉴를 클릭하면 다시 연다. [사이드바 결정과 근거](2026-10-18-sidebar-toggle-options.md)를 참고한다.

## 비교 시안

시안은 예시 데이터로 만든 독립 HTML이며 실제 저장이나 승인 기능에 연결되지 않는다. 기존 아이콘과 Pretendard를 사용하고 새 의존성은 추가하지 않았다.

1. 사원관리: 조건을 명확히 라벨링하고 표 중심으로 구성한다. 표준 도구 순서는 조회, 입력, 복사, 양식, 업로드, 저장, 다운로드를 따른다.
2. 결재 상세: 왼쪽 요청 목록과 오른쪽 상세를 함께 배치한다. 신청 정보, 사유, 결재 진행, 처리 동작을 구분한다.
3. 인사기본: 개인 요약과 의미별 정보 섹션을 사용한다. 단일 값마다 색 카드를 만들지 않고 재직 정보와 연락처, 부가 정보를 나눈다.

산출물은 `frontend/output/common-design-20261018/preview.html`과 `proposal-employee.png`, `proposal-approval.png`, `proposal-profile.png`다. HTML 상단에서 화면과 밝음/어두움을 전환할 수 있다.

### 나란히 비교와 추천 방향

세 화면을 같은 배율로 비교하는 자료는 `frontend/output/common-design-20261018/comparison.html`이다. 전체 화면과 본문 중심 보기를 전환할 수 있고, 각 화면을 누르면 확대된다. 현재 시안을 보존한 비교 자료이며 아래 내용은 다음 설계 보완을 위한 추천이다.

공통 스타일은 사원관리의 정돈된 데이터 중심 구도를 기준으로 삼는다. 색, 글자, 버튼, 여백과 검색 규격을 맞추고 각 업무에 맞는 본문 구조를 사용한다.

| 화면 | 공통화에 활용할 부분 | 다음 보완 제안 |
| --- | --- | --- |
| 사원관리 | 검색, 작업 도구, 그리드 순서와 데이터 밀도 | 제목 중복과 검색 여백 축소, 저장 버튼에 변경 건수 표시 |
| 결재 상세 | 목록과 상세를 함께 보며 연속 검토하는 구도 | 긴 문서에서도 처리 동작 위치 유지, 목록의 굵은 선택선 제거, 좁은 화면은 목록과 상세를 단계적으로 전환 |
| 인사기본 | 구성원 요약과 재직 정보, 연락처 등 의미별 섹션 | 라벨과 값 간격 축소, 기본 정보는 폼 저장, 다건 이력 탭은 그리드와 탭 단위 저장 |

공통 보완안은 본문 여백 24px, 요소 간격 8px와 16px, 헤더 조작 32px, 본문 입력창과 버튼 36px다. 표는 기존 34px 행과 36px 머리글을 기준으로 삼는다. 제목은 본문에 한 번 표시하고 상단은 이동 경로와 공통 도구에 집중한다. 메뉴 선택은 확정된 테마색과 Bold를 사용한다. 데이터의 현재 선택 행은 업무 대상을 알아볼 수 있도록 옅은 배경을 허용한다. 이 제안이 전 화면 구현 완료를 뜻하지는 않는다.

## 결정 당시 검토 항목

- 사원관리의 데이터 밀도와 검색 영역 높이가 적절한가.
- 결재 상세는 목록과 함께 보이는 구도가 적절한가, 현재의 별도 상세 흐름을 유지할 것인가.
- 인사기본은 단일 값 카드 대신 정보 섹션 구도로 전환할 것인가.

사용자가 세 화면의 추천 방향과 실제 적용을 승인했다. 내부 화면 정리 이후에 기존 17장면 랜딩 계획으로 진행한다. 기존 로그인과 물결 배경은 보존한다.

## 확정 후 구현

- 사원관리: 본문 제목 1개, 검색 라벨과 정렬, 보조 도구 분리, 저장을 다운로드 앞에 배치. 기존 변경 건수와 atomic batch, 붙여넣기, 실행 취소를 유지한다.
- 결재 상세: 기존 체크 선택과 일괄 처리/다운로드를 유지한 그리드 옆에 문서 상세를 배치한다. 클릭 또는 Enter로 문서를 선택하고 좁은 화면에서는 목록과 상세를 전환한다. 승인과 반려는 확인 후 별도 처리한다.
- 인사기본: 정보 카드 나열을 재직/추가 정보 섹션으로 바꾼다. 발령부터 평가까지 8개 이력 탭은 같은 그리드를 사용하며 추가/수정/삭제를 모아 한 번에 저장한다. 기본 정보는 폼 단위로 저장한다.
- 미저장 보호: 조회, 이력 페이지/탭/직원 변경, 메뉴 링크, 업무 탭과 빠른 이동을 확인창으로 보호한다. 새로고침과 창 닫기는 브라우저 경고를 사용한다. 브라우저의 뒤로/앞으로 기록 자체는 별도로 가로채지 않는다.
- 랜딩은 내부 화면 정리가 끝난 뒤 진행한다. 이번 세 화면 작업에는 랜딩 코드 변경을 포함하지 않는다.

## 검증 범위

- 실제 로컬 화면에서 레일 72px, 메뉴 56px, 사이드바 scrollbar-width none, 본문 6px, 공통 검색 카드 6px를 확인했다.
- 추가 브라우저 회귀 검사는 짧은 높이에서 숨겨진 스크롤바의 휠 동작과 마지막 메뉴의 키보드 접근을 확인한다.
- 접기 검사는 닫기 버튼이 레일 밖에 있고, 닫은 뒤 선택 대메뉴로 초점이 복귀하며, 접힌 메뉴가 키보드 탐색에서 제외되는지 확인한다. 같은 대메뉴의 Enter 입력과 다른 대메뉴 클릭으로 다시 열기, 그룹 펼침 상태 보존도 확인한다.
- 비교 시안은 독립 Chromium의 1440 x 1000, DPR 1에서 렌더링했다. 세 화면 모두 문서 가로 넘침이 없고 화면 전환과 접기 동작을 확인했다.
- 앞선 시안의 왼쪽 강조선과 선택 배경은 후속 결정에 따라 제거했다. 키보드 초점 표시와 선택 표시는 구분한다.
- 최종 메뉴 색은 기본/선명 팔레트, 밝음/어두움, 다섯 강조색의 20가지 조합으로 확인했다. 선택 글씨 대비 최솟값은 레일 6.15:1, 세부 메뉴 4.62:1이다. 선택 배경은 투명하고 글씨 굵기는 700이며 선택 강조선은 생성되지 않는다.
- B안 적용 화면은 `frontend/output/common-design-20261018/sidebar-b-blue.png`, `sidebar-b-red.png`, `sidebar-b-dark.png`, `sidebar-b-closed.png`, `sidebar-b-mobile.png`에 기록했다. 합성 테스트 데이터로 실제 앱을 렌더링한 화면이다.
- 빌드와 전체 회귀 최종 결과는 TASK_LEDGER에 기록한다. 배포는 수행하지 않는다.
