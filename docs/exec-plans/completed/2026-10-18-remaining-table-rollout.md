# 남은 표 9개 공통 그리드 전환

상태: 구현과 관련 검증 완료. 결과는 `docs/design/2026-10-18-remaining-table-implementation.md`에 기록했다. 랜딩은 최신 17장면 설계 문서로 이어 간다.

사용자가 나머지 9개 전환과 저장 버튼 기반 일괄 반영, 예외 유지, 내부 검증 완료 후 랜딩 단계 진행을 승인했다.

## 범위와 위험

- R2: 공통 그리드, 등록부, 편집 상태와 기존 batch API 연결. 편집형 G01/G02/G03/G04와 조회형 G07/G08/G09/G10/G11을 처리한다.
- 신청서 코드와 결재선 템플릿, 부서 배정과 개인 근무 예외는 기존 다건 저장 계약을 재사용한다. 트랜잭션 원자성은 실제 DB 검사로 확인한다.
- 조회형 5개는 금액과 집계값을 편집하지 않는다. 승인, 신청, 마감, 전표 확정 등 기존 명시적 업무 동작과 권한을 유지한다.
- 문서/분석/권한 매트릭스 7개 예외와 미연결 표 1개는 보존한다. DB 스키마, 급여 계산, 근무 일정 생성 의미, 인증/권한 정책과 배포는 변경하지 않는다.

## 실행 순서

1. 네 편집 화면에 재사용 가능한 기존 공통 모듈 기반 batch 그리드를 연결한다. 새 행, 삭제 복원, 원본 복귀, 실패 보존과 중복 저장 방지를 검증한다.
2. 결재선 단계는 템플릿 초안에 포함하여 함께 저장한다. 근무코드의 여러 편집 영역은 독립 저장 단위이며 화면 이탈은 모든 미저장 영역을 확인한다.
3. 조회형 5개를 공통 읽기 전용 그리드로 바꾸고 명세서/세금 요약 등의 예외는 유지한다.
4. 전환 대상과 예외를 다시 전수 대조한다. 각 대상의 화면 캡처, 편집 전 서버 쓰기 없음, 일괄 요청, 실패 후 보존, 미저장 이동, 읽기 전용과 업무 확인창을 검사한다.
5. grid validation, lint, 단위 테스트, 기존 관련 업무/공통 UI 회귀, 빌드와 TypeScript, 실제 PostgreSQL 원자성 검사 후 내부 작업 결과를 기록한다. 그 뒤 기존 17장면 랜딩 설계를 이어 간다.

## 정리 계획

교체하는 HTML 표와 즉시 추가/삭제용 코드만 제거한다. 기존 공통 레이아웃, 상태, 도구, 페이지 이동, 확인창, 읽기 전용 그리드를 재사용한다. 네 편집 영역의 반복되는 batch 상태만 공통화한다. 새 의존성은 추가하지 않는다.

공통 저장 화면이 한 페이지에 여러 개 있어도 한 영역의 깨끗한 상태가 다른 영역의 미저장 경고를 우회하지 않도록, 이동 확인을 페이지 전체 기준으로 모은다.
