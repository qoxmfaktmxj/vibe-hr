# 세 업무 화면 공통 디자인 적용

상태: 세 화면 구현과 검증 완료. 결과는 `docs/design/2026-10-18-three-screen-implementation.md`에 기록했다.

## 확정 범위

사용자가 2026-10-18에 비교안의 추천 방향과 실제 화면 적용을 승인했다. 사원관리, 결재 상세, 인사기본 순서로 적용한다. 내부 화면 작업을 마친 뒤 랜딩을 진행한다.

- 위험도 R2: 공통 그리드 표현, 인사기본 이력 일괄 저장 API와 등록부 변경.
- 사원관리의 기존 atomic batch, 권한, 붙여넣기와 실행 취소를 유지한다.
- 결재의 승인/반려는 기존 명시적 업무 동작을 유지한다.
- 인사기본은 기본 정보 폼과 탭별 이력 그리드를 사용한다. 이력 추가/수정/삭제는 저장 전까지 로컬 초안이다.
- DB 스키마, 인증/권한 정책, 급여 의미, 배포와 랜딩 구현은 이번 세 화면 적용 범위에 포함하지 않는다.

## 구현과 검증 순서

1. 사원관리: 제목과 검색 라벨, 여백과 버튼, 저장 건수/순서를 정리한다. 기존 사원 UX 회귀에서 저장 전 쓰기 없음, 실패 후 초안, 삭제 복원과 권한을 검증한다.
2. 결재 상세: 기존 목록과 선택/일괄 처리 기능을 보존하면서 선택 문서 상세를 나란히 배치한다. 좁은 화면에서는 상세에 집중한다. 기존 결재 회귀와 상세 조회/전환/확인 취소를 검증한다.
3. 인사기본: 카드 나열을 정보 섹션으로 정리하고 이력을 공통 그리드로 전환한다. 직원/탭 변경과 조회 시 미저장 보호를 적용한다. 한 직원의 한 이력 분류를 한 서버 트랜잭션으로 저장한다.
4. 공통 검증: grid validation, lint, 단위 테스트, 관련 브라우저 회귀, 빌드와 TypeScript. 이력 batch에는 Java 계약/원자성 검사를 추가한다. 세 화면의 한국어와 좁은 화면을 실제 렌더링으로 확인한다.

## 변경 경계

- frontend: employee-master 검색/도구, hri-task-board 및 상세 보기, hr-basic-workspace/tabs/header, 공통 레이아웃/도구, 필요한 BFF 경로와 테스트.
- backend: HrController, HrRequests, HrApplicationService의 기존 인사 이력 쓰기 경로를 이용한 batch와 관련 테스트.
- config: 인사기본 grid 등록과 page 메타데이터.
- docs: 확정 디자인과 계약, 검증 기록.

## 정리 원칙

기존 그리드 상태/페이지 이동/확인창 모듈을 사용한다. 교체로 불필요해진 인사기본 카드 색상과 HTML 표, 행별 즉시 저장 동작만 제거한다. 승인된 세 화면 외 업무 화면을 함께 재작성하지 않는다. 새 의존성은 추가하지 않는다.
